# Content Pack v1

A content pack describes framework metadata, one immutable-able version, and a requirement tree. It is data, not executable code.

## JSON shape

```json
{
  "framework": {
    "code": "internal-security-baseline",
    "name": "Internal Security Baseline",
    "publisher": "Example Organization",
    "framework_type": "standard",
    "license_type": "internal",
    "license_metadata": {"notice": "Internal content"},
    "description": "..."
  },
  "version": {
    "version_code": "2026.1",
    "title": "2026 baseline"
  },
  "requirements": [
    {
      "code": "GOV",
      "title": "Governance",
      "assessable": false,
      "sort_order": 10
    },
    {
      "code": "GOV.1",
      "parent_code": "GOV",
      "title": "Assign security responsibilities",
      "body": "...",
      "guidance": "...",
      "mandatory": true,
      "weight": 1,
      "sort_order": 20,
      "title_fa": "تعیین مسئولیت‌های امنیتی",
      "body_fa": "..."
    }
  ]
}
```

Translations use dynamic columns/keys such as `title_fa`, `body_fa`, `guidance_fa` or `title_en`.

## XLSX

`manifest` contains key/value rows such as:

- `framework.code`
- `framework.name`
- `framework.publisher`
- `framework.framework_type`
- `framework.license_type`
- `framework.description`
- `version.version_code`
- `version.title`
- `version.publication_date`
- `version.effective_date`

`requirements` contains at least `code` and `title`, with optional `parent_code`, `body`, `guidance`, `assessable`, `mandatory`, `weight`, `sort_order`, and translation columns.

## Import guarantees

- Dry-run validation before commit.
- Duplicate requirement-code detection.
- Parent references validated before commit.
- Database commit is atomic.
- Source file SHA-256 is recorded in version metadata/audit output.
- Version can be locked; lock makes requirements immutable and generates a canonical checksum.
